# Checklist qualité de conception

- Le problème est formulé clairement.
- Le public cible est identifié.
- Le MVP est séparé du hors périmètre.
- Les règles métier sont testables.
- Les données sensibles sont identifiées.
- Les intégrations externes sont listées.
- Les choix d’architecture sont justifiés.
- Les risques sont priorisés.
- Les tests essentiels sont définis.
- Les décisions ouvertes sont visibles.
- Le passage au développeur contient assez de contexte.
